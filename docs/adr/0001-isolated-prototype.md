# ADR 0001: 独立施工的 Studio 原型

> 命名说明：本文按创建时的名称记录 Cyrene-Studio；该仓库已于 2026-09-25 更名为 Cyrene-Client。下文保留当时的路径和名称，作为历史背景。

状态：本地原型已选择；正式 Product 边界和公开 API 尚未冻结。

后续登记（2026-09-21）：用户已授权将 Studio 挂载到 IDEA 工作区，并在 `DoHorizon-AI/Cyrene-Studio` 建立独立仓库。下文的“不修改 Workspace”描述最初施工边界；后续仅增加 Studio 的仓库和 IDE 登记，未改变其他 Product 的业务代码或统一发布锁。

## 背景

目标是覆盖完整训练流程、部分 Agent 功能插件，以及云服务器和算力平台管理的模块化流水线编辑平台。用户要求先尝试施工，并尽量避免影响其他项目。

## 本轮决定

1. 在 `Cyrene-Services/Cyrene-Studio` 建立独立、可运行和可测试的项目。暂不修改 `repositories.yaml`、IDE 文件、启动安装脚本或 release-lock。
2. React 应用只通过局部适配层使用 LiteGraph 核心包。采用精确 npm 版本及锁文件，不修改相邻的 LiteGraph 上游研究仓库。
3. 图文档由独立的 Zod schema 描述，包含版本化节点、具名类型端口、边及单独的布局。导入先完成结构和语义检查，再更新画布；不反序列化任意 LiteGraph 节点。
4. 页面预演仅计算 DAG 顺序；不调用 `LGraph.start()`、`runStep()`，节点没有执行处理器。所有 Product 和云端适配器尚未实现。
5. 第一阶段不建立空后端、假 API 或模拟成功的云实例。未来后端应独立验证同一契约，不能信任浏览器校验结果。

## 后续权威归属（设计意图）

Studio 拥有流水线定义、版本、跨 Product 的步骤依赖和步骤到任务的引用。Catalyst 保留 DatasetVersion，Yield 保留训练任务和模型版本，Echo 保留 EvaluationRun，Reactor 保留部署，Navigator 保留 AgentRun。各服务实际可用的 API 和接入方式必须逐个核验。

算力节点当前仅声明目标环境、加速卡与数量。正式云接入需要定义供应商实例、资源池和配额的管理责任，再与 Platform 的资源事实、租约、进程管理衔接。不能把新供应商管理能力当作现有 Platform 已实现的功能。

Plugin 能力不自动等于可执行流水线节点；需要明确描述输入输出、配置 schema、版本和所属 Product 的适配。训练节点内重试归 Yield；整个流水线重试或继续推进归未来 Studio 协调器，不能重复创建同一外部任务。接入写操作前实现稳定请求标识、幂等提交和中断恢复。

## 适配层发现

- LiteGraph 0.7.14 通过 constructor 相等检查画布类型，因此使用实例组合而不是继承画布类。
- 上游事件清理遗漏部分监听器及 capture 参数；在当前画布实例内补全，覆盖 React StrictMode 的挂载/卸载周期，不修改依赖源码。
- 原生菜单、搜索、原生剪贴板及文件拖入可绕开节点目录，当前使用自有节点库与经过校验的 JSON 入口。
- JSON round trip 保存稳定的业务节点与连线 ID；LiteGraph 内部 ID 不作为业务标识。

## 下一步验收顺序

1. 用户评审画布、节点库和参数面板；完善必要的交互，如撤销重做、自动布局、分组。
2. 明确数据处理步骤、数据切分、评估门禁、审批及算力分配的模型。迁移原型契约并补充兼容测试。
3. 建立 Studio 自有 API、文档与运行持久化；先接只读目录，再接隔离环境下的一条完整训练链路。
4. 实现后端幂等执行、恢复、取消、重试、版本锁及权限后，才打开真实资源写操作。
5. 独立构建与集成验收通过后，再以小范围变更登记 Workspace，并决定现有 UI 页面迁移策略。
